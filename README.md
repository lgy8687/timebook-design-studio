# 可视化设计模块：项目交接

## 项目位置

- 本地文件夹：`GitHub/timebook-design-studio`
- 公开仓库：<https://github.com/lgy8687/timebook-design-studio>
- 网页地址：<https://lgy8687.github.io/timebook-design-studio/>
- 当前入口：`index.html`，单文件 HTML，包含 CSS 与 JavaScript，可直接用浏览器打开。
- `unified.html` 是统一工作台：大画布及手机容器均可放元素，单个元素拖入或拖出时按其中心位置改变归属；移动容器时内部元素跟随。支持多选、对齐辅助线、选中快捷操作、按类型显示参数、简单交互预览和复制尺寸或所选参数。选择容器时复制内容包括其内部元素。画板尺寸是可修改的参考值；功能区外框嵌套、真实 App 界面导入、自适应约束、完整图标及图表库尚未实现。草稿保存在当前浏览器独立键 `timebook-unified-workspace-v1`，与两个原型互不自动迁移。
- 统一工作台当前版本 **v0.7.1**：提供多选统一外框与画布快捷键（复制、粘贴、全选、创建副本、删除和取消选择，文本输入不拦截）；对象复制仅支持当前工作台会话；右侧提供设计、交互、复制给 AI 三个面板；支持容器填充、描边、圆角和横向／纵向自动排列，子元素可设置容器变宽或变高时的边距／居中／拉伸约束；支持多选对齐及按钮、按钮组、图标点击预览设置。自动布局目前只支持单行或单列，不支持自动换行；不支持容器嵌套、内容裁剪、交互跳转和弹窗。左侧提供三星手机容器预设和图标库；右侧按钮组提供 A–F 六种基础样式。点选或框选后，在选中对象上（容器则是内部空白处）按住左键拖动即可移动，框选/多选后拖任意选中对象可整体一起移动，容器与内部元素作为一组联动（不会双重位移）；拖动对象时显示对齐参考线，包含三类：边缘对齐（左右/上下）、中心点对齐（横向/纵向）、以及三个及以上对象间距相等时的等间距分布线（对标 Figma 智能参考线，v0.6.5 新增等间距、并让边缘与中心线可同时多条显示）；修复了切换手形/框选工具后容器移动失效的 bug（原因是 setTool 重新开启了原生 draggable 与自定义拖动冲突）；在大画布空白处按住左键拖动框选，碰到即选中；已移除容器锁定功能；删除容器时，其内部元素保留并移到大画布；手形工具平移画布视野；按钮和图表提供基础样式，支持粘贴符合格式的 JSON 参数生成设计元素。
- `studio.html` 是独立的中文自由设计工作台试用版，使用 GrapesJS 和 daisyUI；可添加外框、按钮、卡片和 SVG 图标，点选画布内容后在右侧分组调整布局、尺寸、留白、文字与外观，并将草稿保存在本浏览器。它尚未连接统计预览或时间记录 App。
- `canvas.html` 是基于 Konva 的自由画布第一稿：可拖动对象、碰到即选中的框选、Shift 多选、自动对齐参考线、调整单项参数、复制所选参数和保存本地草稿；提供参考手机尺寸及自定义尺寸。元素暂为独立对象，外框尚不能容纳或关联子元素，图标和图表为示例。画布坐标尚不是手机自适应布局规则。
- 第三方代码及许可保存在 `vendor/`，GrapesJS 为 BSD 3-Clause，daisyUI 和 Konva 为 MIT，Lucide 图标为 ISC。

这是独立项目，不是时间记录 App 的一部分；不要在未明确授权的情况下修改、发布或迁移时间记录 App 的数据。

## 用户真正想做的东西

一个自由、通用、可视化的界面设计工具，而不是只能挑选固定按钮皮肤的页面。用户想先自己组合、看效果、选定方案，再决定用于哪个项目、哪个功能区。

设计分两层：

1. **功能区（围栏）**：可选择方形、圆角矩形、椭圆等外形，并调整尺寸、边框、背景、内边距以及组件间距。
2. **交互区（按钮）**：可选择方形、圆角、椭圆、胶囊等外形；调整按钮数量、排列行数、选中和未选中状态、颜色及文字。现有六种预设可作为可修改的起点，而非选择上限。

“行数”目前理解为按钮排列的行数，尚需在设计时与用户核实细节。用户尤其在意手机上的实际观感、留白、等宽选项和可直接比较，不希望由 AI 反复猜测样式。

## 当前已实现

- A–F 六种胶囊选择框预设，能在两项和四项示例中点击切换。
- 调整字号、按钮高度、边框粗细、选项间距、选中颜色及边框颜色。
- 设计选择与统计页面预览并排展示（窄屏上下排列）；预览中四组选择框同时应用当前草稿样式与参数。
- 可复制当前方案文字、恢复默认；草稿存放在当前浏览器的 `localStorage`，键为 `capsule-design-studio-v1`。不同浏览器、设备和来源不自动同步。
- 统计预览使用固定示意数据，仅用于展示样式；切换按钮只演示选中效果，不连接统计数据或时间记录 App。

## 尚未实现与待讨论

- 独立编辑功能区外框形状、尺寸、背景和内边距。
- 自由编辑按钮形状、数量、行数、文案、选中／未选中状态与布局。
- 预览页中指定某一个位置应用方案；目前四组按钮会一起变化，不能逐个指定。
- 将多个方案保存为可命名、可导入／导出的设计库；当前只有本地单份草稿。
- 实际 App 与该工具的自动同步。用户明确说过这个后续再讨论；目前不可承诺一键应用，也不得自动修改线上 App。

曾讨论的可选方向：在预览页选目标编号（如时间／事件、主线／并行）后，仅替换该位置；保存方案供开发者实施。**这是提议，不是已确认的最终流程。**

## 编号与边界

时间记录 App 使用 B、Z、C 标识，用户将 B 理解为固定交互结构的围栏，数据变化不必换 B，围栏内部交互结构变化则需区分；C 用于可复用模板。该约定属于目标 App，不等于这个独立工具已经实现了完整编号系统。

为避免误操作：

- 不把示例数据冒充用户真实数据；不把预览上的动作说成真实统计。
- 默认只保存或展示设计方案；应用到任何实际 App 前，要明确目标和影响范围。
- 拆分事实、建议和未确认需求；不要宣称尚未实现的功能已完成。
- 按用户需求先讨论或设计，若用户要求实现则实现并验证；不要仅靠换颜色或圆角宣称完成通用工具。

## 后续接手建议

1. 先查看本项目当前代码和 Git 状态，保留已有修改。
2. 和用户确认优先做功能区还是交互区，尤其是外框与按钮组合、排列行数及预览操作。
3. 设计可扩展的方案数据结构，并考虑草稿兼容、导入导出和设备间迁移。
4. 先实现真实可用的编辑与预览，再验证窄屏、长文字、无障碍和边界值。
5. 只有用户明确要求时，才将选定方案整合进时间记录 App 并单独验收。
